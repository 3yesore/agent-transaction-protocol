# Kernel Reduction Audit

Generated by experiments/reduction/run.ts.

The ATP-0002 freeze states eight constraints and calls the kernel
D = (S0, R0) with R(S, X, C, S') -> valid / invalid. This audit makes
'push this constraint into R' a literal operation (experiments/reduction/kernel.ts)
and then looks for constraints the operation cannot absorb.

Two things are deliberately NOT tested, because they would be circular:

1. whether a constraint can be written as a predicate on R's arguments - it always can,
   since the kernel imposes no shape on R;
2. whether the resulting domain is still 'ATP' - the freeze answers that by definition.

The real question is narrower and answerable: **is there a constraint that constrains
which R is consulted, or how many domains exist, rather than what any R accepts?**

## Detail

### C1 - reducible to R

**Constraint.** A protocol-recognized state effect must be justified by the domain's transition semantics.

**Source.** SPEC.md section 3; RFC section 4; invariant 1

**Reducible.** yes - Definitional. It restates what R is. There is nothing to push anywhere.

**Residual.** none - carries no information

**Method.** not a testable restriction: it quantifies over R rather than constraining it

| Check | Held | Detail |
|-------|------|--------|
| C1 is the definition of recognition, not a restriction on it | yes | a recognized effect is one that R returns valid for; the statement is true of every R by construction |
| C1 holds for an arbitrary R | yes | any R satisfies C1 |
| C1 holds for an arbitrary R | yes | any R satisfies C1 |

### C2 - **not reducible to R**

**Constraint.** A semantic update must be recognized under the preceding semantic context.

**Source.** SPEC.md section 4; RFC section 3; invariant 2

**Reducible.** no - It constrains WHICH relation is consulted, not what any relation accepts. A relation is given (state, input, context, successor) and never learns which relation the kernel chose; that choice is made above it.

**Self-sustaining.** **no**

**Residual.** the kernel's one substantive rule: evaluate a transition under the semantics in force BEFORE it

**Method.** same relations, same transition, both evaluation orders; the outcome differs, so the rule is not in the relation

| Check | Held | Detail |
|-------|------|--------|
| under pre-state evaluation a domain cannot authorise its own semantic replacement | yes | the transition carried no recognisedBy, and reflexive rejected it |
| under successor evaluation the identical transition succeeds | yes | the successor authorised its own adoption: self-authorisation |
| a properly authorised semantic update still succeeds | yes | so the rule permits semantic evolution, it only orders it |
| and no relation can prevent it, because the successor names the relation that judges it | yes | the proposer supplies the successor, so the proposer selects the relation consulted - the same hole as proposer-supplied policy parameters in v0.1 |

### C3 - reducible to R

**Constraint.** Recognized historical evolution cannot silently be replaced as if it never occurred.

**Source.** SPEC.md section 5; RFC section 5; invariant 3

**Reducible.** yes - R decides what a successor may contain, so history preservation is R's business. The freeze itself makes it conditional: rewriting is a violation 'when the domain's rules prohibit such rewriting'.

**Self-sustaining.** **no**

**Residual.** none beyond R - and the constraint dissolves as soon as the domain adopts semantics that do not carry it

**Method.** probeReduction, then a two-step run that adopts a relation without the constraint and then erases history

| Check | Held | Detail |
|-------|------|--------|
| C3: the bare relation accepts the violating transition | yes | permissive R accepted it, so nothing at the kernel level stopped it |
| C3: pushing the constraint into R rejects the same transition | yes | withConstraint(permissive, C3) is a legal R and it rejects |
| C3: the kernel required no change to accommodate the reduction | yes | both registries are ordinary kernel instances; the kernel has no shape check on R |
| a domain can legitimately discard the constraint by changing its own semantics | yes | after adopting a permissive relation the second transition erased historyKept; nothing in the kernel objected |
| so C3 is only in force while the domain chooses to keep it | yes | not self-sustaining |

### C5 - **not reducible to R**

**Constraint.** A shared uniqueness invariant requires a shared semantic domain.

**Source.** SPEC.md section 14; RFC section 12

**Reducible.** no - Not because R is restricted, but because a joint constraint over two independent domains is a function of both states, and no R receives both. It is a statement about how many domains exist, not about what a domain may do.

**Residual.** architectural: you must instantiate a third domain, which the freeze already says

**Method.** run both domains locally, then test whether either domain's outcome depends on the other's state

| Check | Held | Detail |
|-------|------|--------|
| two independent domains can both validly grant the same unique resource | yes | D1 and D2 each returned valid for GPU-X |
| and the outcome of one domain is invariant under arbitrary changes to the other | yes | D1's validity is a function of D1's own arguments only; no R1 can therefore enforce a joint predicate |
| a shared domain does enforce it | yes | the first grant is recognised, the second is refused |

## Conclusion

Of the eight constraints the freeze states, **six reduce to some R**, **one is
not a constraint on R at all**, and **one genuinely resists reduction**:

- **C5 (shared uniqueness)** resists because a joint predicate over two independent
  domains is a function of both states, and no R receives both. The audit shows a
  domain's outcome is invariant under arbitrary changes to the other domain's state,
  so no local relation can enforce it. This is an **architectural** residual, and the
  freeze already states it: instantiate a shared domain. Real result, but not a kernel
  constraint.
- **C2 (semantic reflexivity)** resists for a different reason: it constrains *which*
  relation the kernel consults, and that choice is made above every relation. The audit
  holds the relations fixed and changes only the kernel's rule; the outcome flips from
  rejected to accepted, and no wrapping of any relation recovers it.

### The kernel is not empty - it is exactly one rule

~~~text
D = (S0, R0)
R(S, X, C, S') -> valid / invalid
evaluation: the semantics in force BEFORE the transition
~~~

That third line is the whole kernel. It is what makes a domain unable to authorise
its own semantic replacement. Remove it and the kernel becomes empty, which the audit
demonstrates directly: with successor evaluation, the identical relation set accepts a
self-authorising semantic change.

The freeze states this rule but files it as invariant 2 among semantic constraints,
alongside C1 (definitional), C3 (conditional on R and not self-sustaining), and C8
(a permission). Reading the invariant list, it looks like the kernel constrains a lot.
It constrains exactly one thing, and that thing is about evaluation order rather than
about meaning.

### Weakest stated constraint

C3 is reducible **and** not self-sustaining: the audit adopts a relation without the
constraint and then erases history, and nothing objects. The freeze hedges this already
('a semantic violation when the domain's rules prohibit such rewriting'), which concedes
the point. Historical integrity is a domain choice, not a kernel property.

### Falsifiers

This audit is refuted by any one of:

1. a constraint that is not definitional, not a permission, not about composition, and
   not reducible to some R;
2. a demonstration that pre-state evaluation *can* be recovered from inside a relation,
   which would make C2 reducible and the kernel empty after all;
3. a joint constraint over independent domains that some pair of local relations does
   enforce, which would make C5 reducible and leave only C2.

None was found here. The honest statement of the frozen result is therefore:

> ATP-0002 reduces to one rule about evaluation order, plus a free relation.
> Everything else is definition, permission, or architecture.
