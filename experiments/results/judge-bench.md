# Judge Benchmark

Generated by experiments/judge-bench/run.ts.

The question is not how accurate a judge is. It is what the protocol does
with the judge's errors. ATP's failure modes are asymmetric: a wrong AFFIRM
releases value and, per I7-I9, cannot be rolled back, whereas a wrong DENY
only delays. Cost model: release 1.00, deny 0.05, failure to judge 0.10.

## 1. Accuracy is not the metric

Two judges with **identical accuracy** and different error asymmetry.

| trigger-happy (p=0.15) | 14.8% | 0.0% | 92.6% | **0.0740** |

## 4. Does a real decision model fit the Decision schema?

- rationale mode **none**: REFUSED: refusing to publish a non-conforming decision: rationale must be at least 12 characters; a bare score is not an auditabl
- rationale mode **restatement**: conformed, rationale = "decision-4b:latest selected AFFIRM from the supplied options with prob"

The second result is the finding: the model that was trained to choose cannot
produce a basis, and the workaround that satisfies the schema is a restatement
of the choice rather than a reason for it. ATP's rationale requirement is
syntactic. Making it meaningful needs a separate mechanism.
