# A-Coin

Generated by experiments/a-coin/run.ts.

A-Coin is the protocol framework's own unit of account: a higher-level state schema, not
a kernel primitive, exactly as the freeze requires. What matters about it is not the
schema - a balance is a number - but the invariant it carries.

> The total supply is a SHARED UNIQUENESS INVARIANT.

Two independent domains can each mint A-Coin for the same agent and neither is internally
inconsistent. That is the freeze's own condition for when shared state is required, so
A-Coin is the first thing in this project that NEEDS a chain rather than merely allowing
one.

## 1. Conservation inside a domain

| transition | committed | supply |
|------------|-----------|--------|
| genesis | - | 100.00 AC |
| pay 40 alice -> bob | yes | 100.00 AC |
| escrow 50 from alice | yes | 100.00 AC |
| settle 50 out of existence (pay policy) | no | 100.00 AC |

## 2. Issuance is explicit and auditable

| attempt | actor | committed | reason |
|---------|-------|-----------|--------|
| issue 60 AC | treasury | yes | supply below the cap |
| issue 60 more | treasury | no | coin-supply-at-most: supply would reach 120 AC, above the cap of 100 (current 60, delta 60) |
| issue 10 AC | mallory | no | actor-in: actor mallory is not in [treasury] |

## 3. The shared-invariant result

The SAME mint policy text, evaluated in two independent domains and in one shared domain:

| domain | first issue | second issue | agent-x holds |
|--------|-------------|--------------|---------------|
| domain-left | 100 AC | - | 100.00 AC |
| domain-right | 100 AC | - | 100.00 AC |
| domain-shared | 100 AC | refused | 100.00 AC |


This is the freeze's principle instantiated by the currency:

> A shared uniqueness invariant requires a shared semantic domain.

A-Coin is therefore the reason to build the chain. Every other schema in this repository
- commitments, capabilities, outcomes, identities - works fine inside one domain. The
supply does not.

## 4. A-Coin as the measurement unit

Every rate this repository measures becomes a figure in A-Coin once it is attached to
value at risk. Escrow of 300 AC per decision, cost model release 1.00 / deny 0.05 /
failure 0.10.

Rates are copied from the generated reports: the correlated floors from
@@experiments/results/validator-quorum.md@@ and the judge rates from
@@experiments/results/judge-bench.md@@.

| configuration | source | false AFFIRM | expected loss per decision |
|---------------|--------|--------------|----------------------------|
| one validator, correlated at rho=0.2 | validator-quorum | 32.3% | **48.45 AC** |
| 3 validators k=2, correlated | validator-quorum | 25.3% | **37.95 AC** |
| 7 validators k=4, correlated | validator-quorum | 20.9% | **31.35 AC** |
| 3 validators k=2, independent | validator-quorum | 6.3% | **9.45 AC** |
| qwen2.5:1.5b as judge | judge-bench | 16.7% | **25.00 AC** |
| decision-4b as judge | judge-bench | 8.3% | **12.50 AC** |

## Conclusion

**1. A-Coin is an extension schema, and it is the one that needs a chain.** Conservation
   is enforced by a policy rule for transfers and by a ledger invariant for issuance, so
   neither a careless transition nor a mislabelled one can change the supply unnoticed.

**2. The supply is a genuinely shared invariant.** The same mint policy is correct in a
   shared domain and double-counts across two independent ones, with both ledgers
   internally consistent. That is the freeze's condition for shared state, satisfied.

**3. A-Coin is an instrument, not a feature.** Once value at risk is denominated in AC,
   every earlier result - a judge's false-affirm rate, a quorum's correlated floor -
   becomes a cost per decision. The purpose-built decision model costs 12.50 AC per decision against 31.35 AC for a seven-validator correlated quorum.
