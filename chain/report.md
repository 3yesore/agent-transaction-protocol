# Single-Writer Chain Skeleton

Generated by chain/run.ts.

ATP-0002 permits several valid successors and does not require canonical selection. This
skeleton adds exactly two things over a bare Domain - a canonical state root and a
selection rule - and those are the two things the freeze declares optional. There is no
consensus, and none is needed to see the point below.

## The same candidates, different selectors

Three competing successors from one parent, submitted in two different orders. A node
only knows the order in which transitions reached it, so order-dependent selection
makes two honest nodes disagree.

| selector | order A->B->C | order C->B->A | agrees across arrival order |
|----------|---------------|---------------|---------------------------|
| arrival-order | c-agent-a-slot/1 | c-agent-c-slot/3 | **no** |
| lowest-state-root | c-agent-c-slot/3 | c-agent-c-slot/3 | yes |
| actor-priority | c-agent-c-slot/3 | c-agent-c-slot/3 | yes |
| retain-all | none | none | yes |

| selector | what it does |
|----------|--------------|
| arrival-order | the first transition to reach this node is canonical |
| lowest-state-root | the lexicographically smallest resulting state root is canonical |
| actor-priority | an out-of-band priority list decides, falling back to the state root |
| retain-all | no canonical selection; every valid successor is retained |

## The chain client passes ATP-0002 conformance

| probe | verdict | detail |
|-------|---------|--------|
| P1-genesis | passed | genesis semantics = "policy/guard" |
| P2-pre-state-evaluation | passed | verdict = invalid; a conforming implementation consults the semantics in force before the transition |
| P3-permitted-evolution | passed | verdict = valid; the rule orders semantic change, it does not forbid it |
| P4-ordinary-transition | passed | verdict = valid |
| P5-determinism | passed | first = invalid, second = invalid |

## What this establishes

1. **Canonical selection is a choice, and a consequential one.** Two honest nodes that
   saw the same three valid successors in different orders agree only if the selector is
   order-independent. The kernel has no opinion, which is exactly what the freeze says.

2. **The skeleton is thin on purpose.** A state root and a selection rule are the whole
   addition. Consensus, ordering, finality and fees are absent because the reduction work
   showed the protocol content is not there.

3. **The client passes conformance, including P2.** The semantics live at policy/guard in
   state, and a semantic change is authorised by the semantics it replaces. That is the one
   rule the kernel actually imposes, and this is what a shipped client would have to
   demonstrate.

The remaining question is not the skeleton but whether two independent clients would ever
agree on an amendment. That is the next experiment.
